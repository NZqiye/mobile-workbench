# Slow Horses 搜索后“加不进去”排查结论

检查时间：2026-10-19 20:42（Asia/Shanghai）。

## 结论

当前浏览器里的 Slow Horses 已经存在于观影片单，状态是“看过的剧”。主要问题不是搜索不到，而是默认隐藏已看作品、重复导入保留已看状态，再加上重复导入返回的记录 ID 与实际保留的 ID 不一致，导致“点了也没出现”的体验。

本轮只诊断：没有点击线上搜索结果执行导入，没有提交观看进度/评分，没有修改业务代码，没有增删云端片单。

## 线上实测证据

1. TMDB 搜索 Slow Horses 返回 HTTP 200，1 条结果，tmdbId=95480，tmdbMediaType=tv。
2. 同一作品详情返回 HTTP 200，可以读取季集数据。
3. 在“追剧日历 → 我的片单”搜索 slow，已有“Slow Horses 看过的剧 · 2022 · 剧集”。
4. “观影评分 → 搜索片单”输入 slow，默认显示“我的片单 0 / 1 部”和“展开看过 1”。
5. 点击“展开看过 1”后显示“我的片单 1 / 1 部”以及“Slow Horses 电视剧 · 看过的剧”。点击这条已有记录后，右侧正常打开作品详情和季集。

## 代码原因

源文件：F:/Codex/个人知识库/01-Projects/手机端个人工作台/mobile-workbench-main/app/page.jsx

### 1. 搜索本地片单仍然隐藏已看作品

- 第 3996 行：completedLibraryOpen 默认 false。
- 第 4020–4028 行：先按搜索词过滤，再在未展开时排除 status === “看过的剧”的条目。
- 搜索命中并不会自动展开已看记录，因此会出现命中 1 部、展示 0 部。

### 2. 重复导入会合并旧记录，不会重新变成“想看的剧”

- 第 6701–6705 行：导入时先创建新 UUID，并设置“想看的剧”。
- 第 6714 行：dedupeConsultations 按 TMDB ID/标题合并重复作品。
- 第 2054–2071 行：mergeConsultationRecord 保留带较新 updatedAt 的旧记录字段；在当前新导入没有 updatedAt 的情况下，旧记录的 ID 与“看过的剧”状态会被保留。
- 因而重复点击导入，不会让已看作品出现在默认未看片单里。

### 3. 重复导入还存在选中错误

- 第 6718 行：返回的是去重之前的 nextItem，而不是去重后实际保留的记录。
- 第 4234–4238 行：评分页面把返回的新 UUID 用作 selectedId。
- 第 4053–4055 行：这个 UUID 不在实际片单里时，effect 改选第一个未看作品。
- 这解释了为何再次点击搜索结果可能跳到别的作品，表现得像没有添加成功。

脚本从真实 app/page.jsx 提取 importTmdb 与去重函数，使用虚构记录和内存网络桩，不访问真实片单。全部断言通过：

- 实际记录 ID 保留 existing-slow-horses，但函数返回 new-import-id。

- 即使模拟 TMDB 写入返回 401，本地保存仍然执行；所以不能把解锁提示误当作本地记录消失的直接原因。

## 另一个独立问题：TMDB 同步鉴权

用户当前页面原先显示“TMDB 片单同步失败：请先在工作台设置中解锁访问”。无 cookie 的只读片单接口请求也返回 401；这能证明接口受保护，但不能据此断言用户浏览器 Cookie 的具体失效原因。

源码中 watchlist 路由通过 lib/access-auth.js 校验工作台会话；importTmdb 捕获同步错误后仍保存本地记录。若需要恢复 TMDB 同步，可先在工作台设置重新解锁，再单独验证同步。不要与默认隐藏问题混淆。

OMDb 辅助详情请求本次返回非 JSON（HTML），前端会捕获并忽略。该异常不是本次隐藏问题的直接原因，本轮未扩大排查其部署原因。

## 最小修复方向（本轮未实施）
