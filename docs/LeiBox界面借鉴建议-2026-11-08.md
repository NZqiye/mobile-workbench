# LeiBox 界面借鉴建议

检查日期：2026-11-08。参考项目：[leishifu666/LeiBox](https://github.com/leishifu666/LeiBox)，仓库快照 `0e5e61b`；[在线组件库](https://leibox.pantoria.cn/components)。

已读取当前仓库的组件索引、组件详情及部分交互源码，并打开在线组件库、实际操作玻璃标签菜单和列表/卡片切换演示。对照本 App 的安卓布局、想法笔记、资产记录、每日安排和设置页；浏览器使用隔离示例数据，没有读取手机私人记录。本文为取舍建议，本轮没有将 LeiBox 组件加入 App。

## 优先优化的地方

| 优先级 | 当前 App 的位置与问题 | 可借鉴的 LeiBox 组件 | 建议落地方式 |
|---|---|---|---|
| 1 | 安卓已经有首页、安排、录入、股市、更多五个入口；“更多”打开左侧长导航，非主要页面都显示为“更多”选中 | [玻璃标签栏展开菜单](https://leibox.pantoria.cn/docs/animations/glass-tab-menu) | 保留五个入口，把“更多”变成底部展开的栏目菜单，显示各栏目名称与当前栏目；选中背景连续移动。手机安全区、菜单关闭与返回必须一起处理。 |
| 1 | 想法笔记的记录列表逐条显示全文、日期、所有标签和编辑/删除；记录变多后会很长，快速记录表单还排在整个列表后面 | [列表卡片堆叠切换](https://leibox.pantoria.cn/docs/animations/collection-layout-morph) | 默认显示标题、日期及两行摘要，点开查看全文；新增入口始终容易找到。若提供视图切换，紧凑列表用于查找，卡片用于阅读；不要把可检索的记录藏进扇形叠牌。 |
| 1 | AI 文字归类、转写及在线刷新需要等待；当前已有状态文字，但操作与结果的变化缺少连续反馈 | [点阵加载](https://leibox.pantoria.cn/docs/animations/ai-generating) | 在对应按钮附近显示小型点阵或三点动画，配合“正在识别”“正在保存”等实际阶段。结束、取消、失败都必须结束动画；不要制造假百分比，也不要用动画代替启动性能优化。 |
| 2 | 保存、添加和奖励按钮已经有全局缩小反馈，但重要操作的结果还可以更容易察觉 | [立体按压按钮](https://leibox.pantoria.cn/docs/animations/tactile-push-button) | 借按下、释放、完成三种状态，为保存、打卡和奖励做轻微按压与完成反馈。保留现有青绿色，避免复制银色金属外观；幸福值在真实成功使用奖励后更新，动画不改变计数规则。 |
| 2 | 笔记标签集中成一行，任务、观影记录也可能出现较多辅助信息；长标题和主要内容容易受到挤压 | [标签叠放展开](https://leibox.pantoria.cn/docs/animations/stacked-metadata) | 日期和重要状态保持可见，额外标签显示“+N”，点击展开。桌面可补充悬停展开；手机不能只依靠悬停。用户已要求删除的 Sci-Fi 标签和未知时间占位不再加入。 |
| 2 | 旅行、资产、纪念日图标库已经分组，但数量较多，查找图标仍要翻分类 | [折边滚动表情选择器](https://leibox.pantoria.cn/docs/animations/folded-emoji-scroll) | 借搜索框固定、分类选择、网格滚动和选中反馈，用现有本地图标。暂不加入 Canvas 折边变形，避免手机图标变形和额外绘制开销。 |

建议第一批做“更多菜单、笔记摘要展开、真实加载反馈”，能同时改善找入口、长列表和等待体验。第二批再做局部按压、标签与图标选择器。

## 比动效更先要处理的视觉问题

1. **卡片层级重复。** 模块标题、内容面板、面板内统计块、输入框和空状态都使用类似圆角边框，资产页尤其明显。保留外层内容卡片，内部用留白和分隔线区分，避免每层都像一张独立卡片。
2. **文字与背景的层次。** 主背景、卡片和输入框都是相近青绿色，分区主要依赖边框和阴影。保持当前色调，让内容表面更清楚，主要按钮仍是最明显的青绿。
3. **表单间距。** 笔记的日期、类型选择在手机上上下贴得较近；统一字段间距、标签和输入框高度，比再加一段进入动画更有效。
4. **动作应解释状态。** 当前已经有页面切换、按钮按压、下拉框展开和打卡选中动画，无需给每张卡片再做一遍进场。新增动效围绕“打开、保存、完成、失败、重试”展开。

## 暂不建议引入的效果

- 专辑封面隧道、渐变环形轮播、粒子滚动、流体物体：适合展示作品或品牌视觉，长期放在个人工作台会增加绘制和资源开销。
- 字符鲨鱼追踪价格路径：演示包含预测路径、概率与波动率信息，不能直接当作真实行情或预测。股市页应继续让价格、成交量和坐标清楚可读。
- 玻璃文件夹扇形展开：可以作为少量归档资料的展示，但不是大批笔记列表的查找方案；本 App 已有多个内容卡片，不宜再叠装饰卡片。
- 桌面流体提示气泡：可用于收窄后的侧栏，但手机不应依赖悬停，现有带文字导航不需要为了效果隐藏文字。

## 接入边界

LeiBox 具有 React 版本，技术上与现有 Next.js/React 兼容。但很多组件是固定演示画布、模拟数据和独立动画核心，复制演示不等于完成真实记录与导航。列表卡片切换还依赖 GSAP，折边选择器涉及 Canvas 和兼容路径。优先用既有 React、CSS 与本地图标实现选定交互，避免整站引入额外框架。

LeiBox 的 README 写明仅供学习，组件详情分别说明设计参考、源码及素材来源，许可并不统一。例如按压按钮的投稿没有独立许可；部分组件说明没有核实原设计许可。借鉴交互并用现有资源实现即可。若后续直接复制源码，需逐组件确认许可并保留要求的声明，不把“有下载代码包”当成统一授权。

检查范围不包含安卓真机帧率、所有组件的完整功能验收或全站无障碍评分。内置资源版本 1.1.4 的构建与发布是本轮另一项独立工作，不代表这些 UI 建议已经实现。

## 已落实的优化（2026-11-08）

根据后续确认，六项建议已用现有 React、CSS 和本地图标实现：

- 安卓“更多”和手机顶部菜单打开底部栏目网格，显示当前栏目；底部选中背景随栏目移动。原生弹层管理焦点，关闭后恢复，锁定实际内容滚动区，支持点空白、关闭按钮、Esc 和安卓返回，预留底部安全区。桌面继续使用侧栏。
- 笔记默认显示标题、日期和两行摘要，点开显示全文及编辑、删除；列表顶部“写一条”定位表单并聚焦标题。标题允许换行，手机日期与类型分行，统一标签和字段间距。
- 笔记保留两个标签，额外标签以“+N”点击展开。收起只影响显示，搜索仍覆盖完整内容和全部标签。
- 快速记录的三点等待提示绑定服务连接、录音权限、转写及归类阶段；增加“取消处理”。取消保留草稿，迟到的响应不再写入。完成和失败停止提示，不显示模拟进度。
- 保存笔记后显示结果；本机保存失败保留输入，不更新列表或发放奖励。幸福值变动增加短确认，继续仅在成功消耗奖励时加1，获得库存不加幸福值。
- 旅行、资产和纪念日图标增加搜索、滚动网格、选中反馈及无结果提示；使用既有本地素材，不引入 Canvas 或新的动效依赖。
- 资产统计和表单去掉重复内层背景与边框，使用留白和分隔线；修复图标选择区撑出手机卡片，笔记正文采用明确的深色文字。

验证记录见[更新记录](更新记录.md)。此为网页界面更新，现有安卓1.1.4可联网获取，无需重新安装；没有连接安卓真机。
