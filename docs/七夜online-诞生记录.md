# 七夜online 的诞生：把自己的生活，装进一个工作台

记录截至：2026年11月7日。

七夜online 从一个手机端网页工作台起步。它要解决的是很具体的日常需要：查看时间和天气、记录生活、安排计划、关注股票与基金，以及记住自己正在追的剧。随着这些功能逐渐集中到同一个地方，一个属于个人的工作台开始成形。

最初的改进围绕“看得明白、记得方便”展开。饮水、饮食、体重和运动记录加入了更直观的统计图表；股市加入分时走势、日K和自选股、观察股分类；语音与文字录入让随手记录少了几步操作。网页逐渐从信息展示页面，变成可以持续使用的日常工具。

转折来自一个直接的问题：“我可以把这个网页端的工作台做成一个手机APP？”项目发起者明确使用安卓手机后，项目在2026年11月6日提供了可安装的安卓版本。它沿用网页作为主要界面，通过安卓外壳接入手机能力，并继续通过GitHub维护代码、发布线上更新。

装进手机之后，实际使用又带来了新的要求。录音需要调用安卓麦克风；底部导航需要方便手指操作；键盘不能挡住输入；返回首页后再次退出，应直接回到后台；App内部不再需要切换到电脑布局。账号登录、数据同步、Markdown导入导出、版本检查与更新，以及本机任务到时提醒，也陆续补进了日常使用流程。

观影记录成为打磨最细的模块之一。从片单、推荐和海报，到按季记录、单集截图、观看百分比和追剧日历，都经过了多轮实际反馈。面对829集这样的长篇内容，列表加入分段浏览、输入集数定位和“已看到这集”；随后又去掉重复的保存操作，改成观看进度自动保存，并修复输入5.5分时界面提前收起的问题。

界面也逐渐贴近个人习惯：时钟按参考图重新排版并保留秒数，卡片圆角、字体和间距统一调整，岁时纪往加入更贴近日常生活的图标。五一从公文包换成野餐篮，牛排、自助餐、西餐、徒步、爬山、游泳等进入图标选择区，按钮只显示图片。

这个App的开发由项目发起者提出需求、提供截图并实际试用，AI协作完成实现、修复与验证。它的功能和界面，是在一次次“这里看不全”“这个操作多余”“这样更符合我的习惯”的反馈中逐步确定下来的。项目发起者同时参与了产品方向和使用体验的决定。

截至2026年11月7日，七夜online已有安卓1.1.3安装版；最新网页更新通过140项自动测试、正式构建和手机尺寸模拟检查。它已经连接起记录、计划、行情和兴趣管理，也保留了继续根据个人生活调整的空间。

当前安卓消息提醒为本机任务到时通知，服务器即时远程推送尚未接入。网页界面更新可在App联网重开后加载，安卓原生能力的升级仍需要更新安装包。

## 这一路踩过的坑

- **装成App还不等于符合手机习惯。** 网页录音、返回键、键盘遮挡和文件下载都需要分别适配安卓；不能只把网页放进WebView就认为已经完成。
- **页面相似，修改入口可能完全不同。** 推荐、片单、评分和观看进度要先写清进入路径。用户指出“这是评分里点进去的观看进度”，才把修改范围明确到正确组件。
- **滑动卡顿也可能是布局方案造成的。** 曾尝试用预估高度替换不在屏幕里的影视卡片，真实高度变化反而改变了页面长度。撤回后统一内容区滚动，避免多层纵向滚动争抢手势。
- **秒钟更新不该拖着整页刷新。** 时钟需要每秒更新，但观影列表不需要；把秒数刷新留在时钟组件内，减少列表重复渲染。
- **输入过程和保存结果必须分开。** 5.5分输入到5时只是草稿，不能据此收起界面；自动保存进度也不能顺带清空评分草稿。
- **自动保存不能无差别监听所有状态变化。** 初始化、切季和定位不是观看操作。只在勾选、取消、全选和“已看到这集”时写记录，并防止较早的同步结果覆盖后续编辑。
- **长篇剧集要提供直接选择入口。** 829集不能只靠滚动查找；分段、跳转和连续看到某集要分别有明确行为，定位不能误记成已看。
- **数据和图片不能靠看起来正确。** 百分比要按真实总集数计算；未知总量不能猜。图片失败应回到同一作品的备用图，加载前后保留宽高占位。
- **手机提醒有不同实现。** 本机任务到时通知、浏览器推送、服务器即时远程推送是三件事；退到后台也不代表App持续运行。
- **更新、签名和存储是复刻时的关键。** 网页与APK分别更新；签名要完整备份才能覆盖升级。App和浏览器的本机记录并不共用，转移数据需要同步或导入导出。
