# 部署与配置

整理日期：2026-11-07。

## 部署

1. Fork或复制 `NZqiye/mobile-workbench`，在Vercel导入自己的仓库。仓库根目录就是Next.js应用目录。独立复刻的域名、数据库与安卓来源替换见[复刻指南](复刻指南与踩坑记录.md)。
2. 在 **Settings → Environment Variables** 配置所需变量并部署；推送到 `main` 会触发正式部署。
3. 打开网站，在“设置 → 账号登录”输入账号和密码。默认账号为 `qiye`；独立复刻者使用自己配置的 `WORKBENCH_ACCESS_CODE`，没有公开默认密码。手机可将网站添加到主屏幕。

本地开发将变量写入 `.env.local`，运行方式见 [README](../README.md)。手机测试本地版本时需要与电脑处于同一网络，并访问电脑的局域网 IP。

## 云同步与访问控制

```dotenv
NEXT_PUBLIC_SUPABASE_URL=你的Supabase项目URL
NEXT_PUBLIC_SUPABASE_ANON_KEY=你的Supabase公开Key
SUPABASE_SERVICE_ROLE_KEY=你的Supabase服务端Key
WORKBENCH_ACCESS_CODE=自行设置的个人账号密码
WORKBENCH_SESSION_SECRET=至少32位的随机会话密钥
```

可选设置 `WORKBENCH_USERNAME` 更改账号名，未设置时使用 `qiye`。

这是一个个人账号，统一授权数据同步、语音和在线服务，不提供多用户注册。云同步使用 `workbench_records` 表，由 `/api/sync` 服务端代理读写，所有者标识固定为 `personal-workbench`。原项目从访问码升级为账号登录时保留原密码和数据归属，无需迁移；独立复刻者应配置自己的密码和数据库。登录时合并两端记录，之后编辑自动同步，自选股与观察股均保留。

新建独立Supabase项目时须初始化 `workbench_records` 表；当前接口所需字段及最小兼容SQL见[复刻指南的登录与数据库部分](复刻指南与踩坑记录.md#22-登录与数据库)。更改登录名不会创建新的数据所有者；多用户隔离需要另外实现。

账号密码和会话密钥必须同时配置。登录通过有效期为 7 天的签名 Cookie 恢复，原有效 Cookie 可继续使用；仅有本地旧“已解锁”标记不会被视为已登录。服务端 Key、密码和私钥不使用 `NEXT_PUBLIC_` 前缀，不提交到 GitHub。退出登录保留本机记录。

### 安全配置与边界

- 仅由本项目服务端访问的独立数据库，可在 Supabase SQL Editor 执行 [supabase-security.sql](../supabase-security.sql)：启用业务表 RLS，撤销公开、匿名及普通登录角色的表级权限，保留服务端读写。不会修改记录；与其他应用共用表时先评估影响。脚本末尾提供权限与策略检查；已有列级授权、函数/RPC及后台成员权限还需单独核查。代码更新不会自动执行生产数据库 SQL。
- 账号密码使用独立的长密码，会话密钥使用随机生成的至少32字节值。后台账号建议开启双因素认证；服务端 Key 仅保存在部署平台。更换会话密钥会使所有设备原 Cookie 失效，需要重新登录。
- 登录按来源 IP 限制10分钟内10次尝试，并限制单实例保存的 IP 数量，429会返回重试时间。此限制仍在实例内存中；上线时还需在托管平台配置跨实例登录限速/防火墙，不能视为完整的分布式防爆破保护。
- 网页响应包含 CSP、防嵌入、禁止类型嗅探、无来源信息及权限限制；语音保留麦克风权限。CSP限制外部脚本、插件和网络连接，允许HTTPS海报与天气；为兼容静态页面及离线启动保留内联脚本，不能独立防止所有脚本注入。本项目停用未使用的 Next 图片优化入口。
- 所有 API 响应禁止浏览器和共享缓存保存；写入接口检查请求来源，JSON请求按实际读取字节限制大小。推送仅接受Google、Mozilla、Apple和Windows官方服务地址，发送前再次验证已保存订阅。
- 退出账号仍保留本机记录，本机记录与完整Markdown备份尚未加密；导出文件含完整恢复数据，请勿公开分享。云同步与AI供应商处理边界仍适用，并非端到端加密。
- 仓库忽略环境文件、部署配置、常见私钥及本项目默认命名的导出备份，仅允许提交不含凭据的 `.env*.example` 模板。忽略规则不能阻止强制提交，也不能清除已有历史中的秘密。
- 2026-11-08 修补运行与开发依赖：锁定安装使用 `package-lock.json`。未调用的Vercel CLI依赖已移除，Git推送触发的托管部署继续使用平台工具；TypeScript检查器的minimatch设定范围覆盖已修复版本，保留既有ESLint配置，已验证实际项目服务与路径匹配。后续更新需同时检查生产和全部依赖，不使用强制降级框架的自动修复。

## 可选功能

| 功能 | 环境变量或配置 |
| --- | --- |
| 语音与文字归类 | 见 [语音录入与配置](在线语音接口配置.md) |
| 影视资料与推荐 | `TMDB_ACCESS_TOKEN` |
| TMDB 片单同步与评分 | `TMDB_ACCOUNT_ID`、`TMDB_SESSION_ID`；需要时补充 `TMDB_USER_ACCESS_TOKEN`、`TMDB_WATCHING_LIST_ID`、`TMDB_COMPLETED_LIST_ID` |
| 热榜时讯 | `DAILY_HOT_API_BASE`；正式使用建议配置自建服务 |
| 浏览器Web Push | `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`、`CRON_SECRET` |

浏览器后台提醒需要先执行 [supabase-push.sql](../supabase-push.sql)，配置推送变量，部署到 HTTPS 后登录并在设置中开启提醒、允许浏览器通知。VAPID密钥与定时入口密钥的生成步骤见[复刻指南的提醒部分](复刻指南与踩坑记录.md#三种提醒要说清楚)。`VAPID_SUBJECT` 使用 `mailto:你的邮箱`。当前定时任务在北京时间每天 10:00 和 15:00 检查到期事项，实际执行时间受部署平台限制，并非分钟级即时提醒。

安卓1.1.3已实现本机任务到时通知，配置方式见[安卓任务提醒](安卓安装与打包.md#app-任务提醒)。它与浏览器Web Push是两套机制；服务器即时远程推送到安卓仍未接入，电脑修改任务后需手机同步才能更新本机提醒。

## 常见问题与维护

- 2026-11-08 安卓 1.1.4 资源内置：网页使用 `bundledAssetUrl` 为安装包覆盖的图片与动画加分组校验参数，安卓在 HTTPS 同源且版本匹配时从 APK 提供文件。版本不匹配、包内没有该文件或旧版 App 时沿用正常网络加载。网页构建自动生成版本表，Service Worker v15 根据响应头跳过内置文件的重复缓存；真实 API 与页面代码继续在线更新。
- 2026-11-08 启动优化：影视发现片单改为首次进入观影记录后加载，首页不请求 TMDB 推荐、动漫更新或 TVMaze 排期。Service Worker 首次接管不刷新页面，已有安装收到新版本仍刷新一次。当前版本脚本、图片等资源使用缓存优先，HTML 使用联网检查更新；已有缓存时等待网络最多 2 秒，随后先显示缓存并在后台保存最新 HTML。账户与其他 API 不从离线缓存读取；视频分段请求沿用浏览器网络处理，避免把部分视频保存成完整文件。静态资源修改后仍须递增缓存版本。
- 提示未登录或返回 401：进入设置重新登录；默认账号为 `qiye`，密码为自己配置的 `WORKBENCH_ACCESS_CODE`。部署环境须具备有效密码和会话密钥。
- 网站或图标仍是旧版本：检查部署状态并刷新 PWA，必要时清除旧 Service Worker。静态资源变更时更新 `public/sw.js` 的缓存版本。
- 影视或热榜服务不可用：核对对应变量和外部服务连接；本机超时不一定是凭据错误。
- 数据修改沿用现有同步流程：更新 `updatedAt`，删除保留同步删除记录；新增集合同时接入云端合并与备份。云端写入保持串行，避免覆盖后续记录。
