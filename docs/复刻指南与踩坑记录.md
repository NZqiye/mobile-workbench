# 七夜online：复刻指南与踩坑记录

整理日期：2026年11月7日。依据本项目实际需求、更新记录、源码和验证记录整理。网页功能基线为提交 `187ad0e`，安卓安装版为1.1.3、版本代码5；这些是当前快照，后续版本以仓库为准。

这份记录面向想复刻一套个人工作台的人。先使用现有功能跑通网页、数据与安卓安装，再根据自己的生活修改。文中区分实际出现过的问题、根据当前源码整理的复刻注意点，以及尚需真机确认的行为。

## 1. 先理解这个App由什么组成

| 部分 | 实际实现 | 复刻时的作用 |
| --- | --- | --- |
| 工作台界面 | Next.js 16.3.5、React、CSS | 首页、记录、图表、行情、片单和设置 |
| 网页服务 | Next.js API，由Vercel部署 | 登录、云同步、影视资料、在线语音等服务入口 |
| 安卓安装版 | Java编写的系统WebView外壳 | 加载线上网页，接入麦克风、文件选择、返回键、更新和本机提醒 |
| 数据 | 本地存储与Supabase | 本机先保存，登录后按现有规则合并并同步 |
| 可选外部服务 | Cloudflare Workers AI、TMDB等 | 提供转写、文字归类、影视资料与推荐 |

`npm run build:android`不会把Next.js服务器打进APK。第一次打开App必须联网；部分已加载内容可能有缓存，不能据此把它当作完整离线App。

网页和浏览器PWA、安卓WebView有各自的存储。安装App不会自动读取手机浏览器的记录；使用相同个人账号同步，或从浏览器导出Markdown后在App导入。

当前登录是**个人单账号**，不是多用户注册系统。`WORKBENCH_USERNAME`只改变登录名；数据所有者仍由 `lib/sync-server.js` 中的 `personal-workbench` 固定标识决定。别人复刻应使用自己的数据库、服务凭据和域名。要做多用户，需要另外实现每个用户的数据隔离，不能只增加几个账号名。

## 2. 推荐的复刻顺序

1. 下载或Fork仓库，把网页在电脑上运行起来。
2. 配置个人登录和独立Supabase数据库，用一条测试记录确认同步。
3. 部署自己的HTTPS网站，确认手机浏览器可以访问。
4. 按需求接入语音、影视等外部服务，逐项验证。
5. 替换安卓源码中的站点、更新仓库和应用标识，打包安装到手机。
6. 用隔离资料检查录音、导入导出、观看记录、提醒和覆盖升级，再导入正式个人数据。

### 2.1 获取源码并运行网页

需要Git、Node.js和npm。Windows可从[Git官网](https://git-scm.com/downloads/win)安装Git，从[Node.js官网](https://nodejs.org/en/download)安装Node.js，npm随Node.js一起安装。安装后重新打开终端，用 `git --version`、`node --version`、`npm --version` 确认工具可用。当前Next.js要求Node.js至少20.9.0，本项目已在Node.js 24环境运行；优先使用仍受支持的Node.js LTS版本。

```bash
git clone https://github.com/NZqiye/mobile-workbench.git
cd mobile-workbench
npm ci
npm run dev
```

默认打开 `http://localhost:3000/`。保留仓库中的 `package-lock.json`，用 `npm ci` 按锁定依赖安装；不要复刻第一步就把依赖全部升级到最新。

手机访问本地预览时，应与电脑在同一网络，使用电脑的局域网IP；手机上的 `localhost` 指手机自己。访问不到时检查服务监听地址、防火墙和网络。局域网HTTP预览不保证浏览器麦克风可用，录音验证优先使用自己的HTTPS部署或安卓安装版。

项目使用Next.js 16.3.5。修改代码前读 `node_modules/next/dist/docs/` 中对应版本说明；旧教程中的命令和API不一定适用。例如当前 `package.json` 保留了 `next lint` 脚本，而Next.js 16已经移除了该命令，不要把它当成可用的验收步骤。

### 2.2 登录与数据库

在项目根目录手动创建 `.env.local`，以下只展示变量格式；真实值用自己的服务配置替换，不要把示例字符串当作有效密钥。

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SERVICE_ROLE_KEY
WORKBENCH_USERNAME=YOUR_LOGIN_NAME
WORKBENCH_ACCESS_CODE=YOUR_PERSONAL_PASSWORD
WORKBENCH_SESSION_SECRET=YOUR_RANDOM_SECRET_AT_LEAST_32_CHARACTERS
```

未设置账号名时默认是 `qiye`，没有公开默认密码；独立复刻者自行设置 `WORKBENCH_ACCESS_CODE`。密码与至少32字符的会话密钥必须同时配置。可在本机用下列命令生成随机会话密钥，结果仅填入自己的环境变量，不放入截图或公开文档：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

修改本地环境变量后重启开发服务；在Vercel修改变量后重新部署。正式登录使用签名Cookie，不能靠本机“已解锁”标记绕过服务端登录。

云同步通过 `/api/sync` 在服务端访问 `workbench_records` 表，当前接口使用 `id`、`page`、`title`、`meta`、`note`、`created_at` 字段。仓库原有SQL只包含推送订阅表；下面是**依据当前接口整理的最小兼容结构**，供全新的独立Supabase项目初始化，不是原生产数据库的完整结构导出，也不是旧库迁移脚本：

```sql
create table if not exists public.workbench_records (
  id uuid primary key default gen_random_uuid(),
  page text not null,
  title text not null,
  meta text not null default '',
  note text not null default 'null',
  created_at timestamptz not null default now()
);

create index if not exists workbench_records_lookup
  on public.workbench_records (page, title, created_at desc);

alter table public.workbench_records enable row level security;
```

在Supabase SQL Editor中执行，再登录自己的工作台验证。接口由服务端 `service_role` 访问，当前方案不需要开放匿名读写策略。已有同名表时先检查字段；`if not exists`不会替你修正不兼容的旧结构。本次整理没有在新建数据库上执行这段SQL，复刻时必须用测试数据验证。

当前写入顺序是插入新快照成功后再删除同类旧快照，不是数据库upsert；不要自行给 `(page, title)` 加唯一约束，否则第二次同步可能因旧快照仍在而插入失败。

不要给 `SUPABASE_SERVICE_ROLE_KEY`、账号密码、会话密钥、Cloudflare Token或VAPID私钥加 `NEXT_PUBLIC_` 前缀。该前缀的变量可能进入浏览器代码。分享仓库时不包含 `.env.local`、真实记录导出、登录Cookie、签名文件和密码。

### 2.3 部署和可选服务

在Vercel导入自己的仓库，以含 `package.json` 的目录为应用根目录，填入相同变量并部署。使用自己的HTTPS域名；推送GitHub成功后还需检查本次提交对应的正式部署是否成功。

| 想复刻的能力 | 自己需要准备什么 | 最小验收 |
| --- | --- | --- |
| 本机记录 | 网页运行环境 | 新增一条记录，刷新后仍在 |
| 云同步 | Supabase表、服务端Key、个人登录配置 | 电脑新增，手机同步后可见；手机删除后电脑不复活 |
| 语音与文字归类 | `CLOUDFLARE_ACCOUNT_ID`、`CLOUDFLARE_API_TOKEN`，Workers AI权限 | 实际录一句话，确认只写入正确栏目且草稿可恢复 |
| 影视资料与推荐 | `TMDB_ACCESS_TOKEN` | 搜索一部作品，打开正确季和单集 |
| TMDB片单和评分同步 | `TMDB_ACCOUNT_ID`、`TMDB_SESSION_ID`，需要时补充用户Token和片单ID | 本机评分保留，外部同步成功或失败有明确结果 |
| 热榜时讯 | `DAILY_HOT_API_BASE`和可访问的服务 | 确认数据来源与刷新、失败提示 |
| 浏览器Web Push | VAPID配置、`CRON_SECRET`、推送订阅表、HTTPS和浏览器授权 | 建立订阅并实际收到通知 |
| 安卓本机任务提醒 | 安卓1.1.3或后续包含该能力的安装版、手机系统权限 | 锁屏收到测试任务，完成后不再提醒 |

语音使用Cloudflare的 `@cf/openai/whisper-large-v3-turbo` 转写，以及 `@cf/qwen/qwen3-30b-a3b-fp8` 归类。它们需要对应服务可用与额度，不是APK里自带的离线模型。当前录音上限60秒、音频上限3MB。具体配置见[语音配置](在线语音接口配置.md)。

## 3. 打包自己的安卓App时必须替换什么

只把APK安装到手机会连接原项目站点。要做自己的版本，应先有自己的可访问HTTPS网站，再修改以下关联位置。建议先保持Java包名和源码路径跑通安装，随后再统一改成自己的应用标识。

| 要修改的内容 | 对应文件 | 容易漏掉的位置 |
| --- | --- | --- |
| 首页与可信站点 | `android/src/cc/qiyeonline/workbench/MainActivity.java` | `HOME`与 `trusted()` 中的主机必须一致，否则原生桥接不会接入 |
| 版本清单网址 | 同目录 `AppUpdater.java` | 清单目前指向原站点 `/app-update.json` |
| APK来源验证 | 同目录 `UpdateSecurity.java` | 校验精确匹配原GitHub仓库、版本和文件名，换自己的仓库后也要修改规则 |
| 构建产物与发布地址 | `scripts/build-android.cjs` | 原仓库Release地址和APK文件名前缀；脚本会生成并覆盖公开更新清单 |
| 应用名称、包名、版本 | `android/AndroidManifest.xml` | `package`、`versionCode`、`versionName`、应用名称和provider权限名 |
| 包名及原生文件地址 | 安卓Java源码、构建脚本、相关测试 | Java `package`、源码目录、提醒action、`content://`权限名必须统一 |
| 更新文件provider | `UpdateFileProvider.java`、`AppUpdater.java`、Manifest | 三处provider authority必须一致，否则安装文件无法交给系统 |
| 网站名称与图标 | `app/`、`public/manifest.webmanifest`、`public/icons/`、README | 浏览器、主屏幕和APK的名称、图标分别检查 |

通过搜索原域名、`NZqiye/mobile-workbench`、`cc.qiyeonline.workbench`、`qiyeonline-`核对遗漏。相关测试包含旧仓库和包名样例，重命名后应一起调整测试。可信来源和下载校验应保留，不要通过允许所有网站访问原生能力来解决连接失败。

### 3.1 构建环境

当前脚本使用JDK 17、Android SDK Platform 36和Build Tools 36.0.0。Windows准备步骤：

1. 安装JDK 17，例如[Temurin 17](https://adoptium.net/temurin/releases/?version=17)。`JAVA_HOME`指向JDK根目录，不能指到 `bin`。
2. 安装[Android Studio或Android命令行工具](https://developer.android.com/studio)。使用Android Studio时，在SDK Manager的SDK Platforms中安装Android API 36，在SDK Tools中安装Build Tools 36.0.0、Platform-Tools、Android SDK Command-line Tools（latest）。
3. 记下SDK Manager显示的SDK路径。`ANDROID_HOME`指向这个SDK根目录，不能指到 `build-tools`。完成所需工具的许可确认。
4. 在同一个PowerShell窗口设置环境变量并构建；下列路径仅为示例，替换为自己的安装位置。若已通过SDK Manager安装并确认许可，可跳过两条 `sdkmanager` 命令。

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk-17'
$env:ANDROID_HOME = 'C:\Users\YourName\AppData\Local\Android\Sdk'
& "$env:JAVA_HOME\bin\java.exe" -version
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" "platforms;android-36" "build-tools;36.0.0" "platform-tools"
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --licenses
```

只下载命令行工具的读者，应先按照官方说明将工具放到SDK的 `cmdline-tools/latest/` 下，再运行上述命令。这些 `$env:` 设置只对当前终端有效；换窗口时重新设置，或通过Windows环境变量设置保存。准备完成后，在项目根目录运行：

```bash
npm run build:android
```

产物位于 `output/android/qiyeonline-版本.apk`，同时生成 `SHA256SUMS.txt` 和更新清单。`output/`被Git忽略，APK应作为自己仓库的Release附件发布。

**实际踩过的坑：Windows安卓工具不能可靠读取中文路径。** 脚本已经把编译过程放到系统临时目录中的ASCII路径，随后复制APK回项目。不要随意改成直接在中文项目路径运行所有Android工具。

第一次构建会生成 `.android-signing/release.jks` 和 `password.txt`。应单独备份完整 `.android-signing/` 目录；后续更新使用同一签名，并增加 `versionCode`。签名丢失后，新签名不能直接覆盖旧App；先卸载还可能丢失本机记录。

自己的Fork第一次生成的签名与原作者签名不同，因此不能覆盖安装原版。若要与原版并存，应使用不同应用标识；如需转移数据，先从原版导出Markdown，再在自己的版本导入。

### 3.2 发布与升级顺序

1. 完成网页与原生改动，检查版本号和应用标识。
2. 用原有签名构建，验证签名及SHA-256。
3. 将本次APK与校验文件发布到对应版本的GitHub Release，并实际下载核对。
4. 检查 `public/app-update.json` 的版本代码、下载地址、哈希、更新说明，再部署网站与清单。
5. 在已安装旧版本的手机上检查更新、下载并覆盖安装，确认旧记录仍在。

不要先发布指向不存在APK的清单。网页界面更新通常只需部署网站；麦克风、提醒、返回键、安装程序等Java能力变更需要新APK。App1.1.2起可以检查和下载更新，安装仍由安卓系统请求用户确认，不能静默安装。

## 4. 实际踩过的界面与业务坑

| 实际问题 | 原因与本项目的处理 | 复刻时怎么检查 |
| --- | --- | --- |
| 修改了错误的观影界面 | “推荐”“片单”“观看进度”不是同一页面；按截图定位到“观影评分→作品→季→观看进度”再改 | 在需求中写出进入路径，先重现，再编辑对应组件 |
| 手机内容显示不全、文字被挤到错误列 | 旧样式层叠，固定宽度、网格列和长文字互相影响；对目标页面收紧作用范围，新增组件使用局部CSS | 检查320像素、正常竖屏、横屏、长标题和字体放大 |
| 圆角和颜色改了仍不生效 | 全局主题规则有较高优先级及 `!important`，影响后来的组件 | 看浏览器最终生效样式，检查八种主题；不要一直追加宽泛覆盖规则 |
| 推荐页下滑有阻塞感 | 曾引入预估高度与可见区域替换，真实卡片高度不同，页面长度变化；撤回该方案，内容区统一负责纵向滚动 | 滑动时观察页面高度和滚动位置，确认没有嵌套纵向滚动争抢手势 |
| 观影页每秒重复刷新 | 时钟推动整页状态更新；将秒钟更新留在时钟组件，整页只在分钟变化时更新时间相关状态 | 稳定页面后观察几秒，确认列表不随秒钟重新渲染 |
| 动漫海报无法显示 | 图片源或链接有问题；优先真实Bangumi海报，TMDB失败后回到同一作品的原图，保留尺寸占位 | 主图失败、备用图失败都测；不要拿其他作品海报凑数 |
| 截图太小，点击图片还误勾集数 | 图片和整条勾选耦合；放大缩略图，图片按钮、勾选和简介分别操作 | 放大与收起图片、展开简介后，观看状态不能改变 |
| 829集只能一直往下滑 | 集数选择只依赖长列表；改为每段40集，加范围选择、定位和“已看到这集” | 跳到700集、切段返回、最后一段、无效编号、全选与取消 |
| 输入5.5时刚输入5就收起界面 | 用正在输入的草稿判断“已评分”；改为已保存评分决定完成摘要 | 全季已看时逐字输入5、点、小数5；保存前不提交、不卸载输入框 |
| 自动保存可能清空旧记录或覆盖评分草稿 | 若监听状态变化保存，会把初始化和切季也当成编辑；改为在明确用户事件中保存，评分与进度同步分开 | 打开作品不写空记录，切季不串数据；输入5.时勾选集数，草稿仍在 |
| 较早的同步结果覆盖新勾选 | 连续操作产生多个异步请求；读取最新本机进度，阻止旧返回值回写新状态 | 快速连续勾选并延迟同步返回，最后一次选择应保留 |
| 观看百分比不可信 | 只计算当前季或拿未知总集数推算；按所有已知季汇总，未知总量不显示比例 | 11/26为42%、12/26为46%；空记录、多季、重复与超范围编号都检查 |
| 日历日期数字参差不齐 | 有无更新提示导致网格行高度不同；固定星期、数字、圆点和提示的行位，使用等宽数字 | 混合有更新和无更新的日期，检查周历与月历每排对齐 |
| 当前集数和“共多少集”挤成两排 | 信息区宽度与字体、海报占位不匹配；调整海报与间距，集数行保持不换行 | 用“第12季、120集、共1200集”检查320像素下不截断 |
| 五一显示公文包，图标选择太啰嗦 | 只按“劳动”字面选办公物件；换成假日野餐篮，按钮去掉文字，按生活场景整理 | 图标语义与用户用途对应；保留稳定ID、选择状态和无障碍名称 |

主要实现位置：观看编辑在 `app/page.jsx` 的 `WatchCheckin`，集数导航在 `app/components/watch-episode-list.jsx`，日历排版在 `app/components/watch-calendar.module.css`，图标定义在 `lib/anniversary-icons.js`。修改前先找组件和数据处理入口，不要只凭页面看起来相似就改。

## 5. 手机能力、数据和提醒的注意点

### 录音不是打开另一个录音机App

原先网页录音不能直接代替安卓原生录音。安装版通过可信页面与安卓消息通道调用麦克风，在本App内录音，再将AAC/m4a送到在线转写服务。录音、通知和更新请求有各自的状态与请求标识，避免通知返回把录音误判为完成。

麦克风权限拒绝后要能恢复；连接尚未就绪、服务不可用和未登录应分别提示。切到后台会取消未保存录音，使用者应先停止并保存。复刻后实测权限拒绝、重新授权、取消录音、后台切换和网络失败，不要只测试顺利录完一次。

### 返回后台不等于后台常驻

正常返回先关闭当前界面或回首页，首页再次返回退到后台；录音中仍提示放弃。后台应用可能被系统回收，没有新增常驻服务。需要后台运行的任务应交给适当的系统机制，不能依赖网页一直执行JavaScript。

### 三种“提醒”要说清楚

| 类型 | 当前状态 | 使用边界 |
| --- | --- | --- |
| 安卓本机任务到时通知 | 1.1.3已实现 | 手机同步过的任务由系统安排；电脑改动后需手机再次同步 |
| 浏览器Web Push | 有配置和订阅流程 | 需要HTTPS、浏览器支持和授权；当前定时检查是北京时间10:00、15:00 |
| 服务器即时远程推送到安卓 | 尚未接入 | 未配置FCM或其他安卓推送服务，不能承诺电脑修改后手机立刻收到 |

浏览器推送另需执行 [supabase-push.sql](../supabase-push.sql)。完成 `npm ci` 后，在项目根目录生成自己的一对VAPID密钥：

```bash
npx --no-install web-push generate-vapid-keys
```

将输出分别填入 `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`，`VAPID_SUBJECT`填写自己的 `mailto:邮箱地址`。用登录配置部分的随机生成命令另外生成 `CRON_SECRET`，作为定时入口的验证密钥；不要与会话密钥共用。配置完成后重新部署，登录并在设置中订阅提醒，实际验证通知到达。私钥和 `CRON_SECRET`仅保存在自己的环境变量中。

`vercel.json` 中UTC02:00、07:00对应北京时间10:00、15:00；复刻者要确认自己的部署套餐支持相应定时频率，不能把定时检查当成准点闹钟。

安卓通知权限、准时提醒权限、强行停止应用及厂商省电设置都会影响提醒。提醒按北京时间解释；跨时区使用需核对。重启与覆盖更新后的恢复逻辑已有实现，系统强行停止后需要重新打开App。本次没有连接安卓真机，锁屏到达与厂商限制仍须复刻者实测。

### 同步和备份必须按数据行为验证

编辑记录保持稳定ID和 `updatedAt`，删除保留删除标记，防止另一端重新合并回来。新增一个记录集合，要同时检查初始化、编辑、云端合并、删除和Markdown备份，不是加一个输入框就完成了数据功能。

Markdown备份包含可读正文和完整恢复数据。不能删除末尾恢复区；编辑可读正文不会自动改变恢复记录。普通Markdown笔记也不是完整备份。安卓导出与浏览器下载走不同路径，曾针对立即撤销临时Blob地址后下载失效的情况做过验证；中文文本须保持UTF-8。用测试数据做一次“导出→独立环境导入→逐项核对”，再依赖它保存正式数据。

退出账号仍保留本机记录，适合个人手机使用；如果借给别人使用，不能把退出登录理解为已经清除了本机数据。正式记录导出包含个人信息，不应放入公开仓库或演示资料。

## 6. 最小验收清单

准备一组与私人记录完全分开的资料：空片单、一部26集作品、一部829集作品、多季作品、长标题、损坏图片、跨日任务和一条含中文的记录。

```bash
npm run build
node --test tests/*.test.cjs
```

140项测试是2026年11月7日的验证快照，未来数量会变化。测试里包含真实Java编译与运行，需要JDK；`tests/android-reminders.test.cjs` 目前按Windows `javac.exe`、`java.exe`调用，使用自己的 `JAVA_HOME`。Linux/macOS复刻者需适配该测试的可执行文件名，不能把“所有平台直接跑全套”当成已验证事实。

| 检查对象 | 必须确认的行为 |
| --- | --- |
| 手机布局 | 320、393像素竖屏与844像素横屏，长文字与字体放大后不截断，底部按钮可到达 |
| 观看记录 | 勾选立即保存；定位不标记；切季不串数据；全选、取消及刷新恢复正确 |
| 评分 | 完季后能完整输入5.5；保存前无评分；保存后实际值为5.5 |
| 图片与滚动 | 加载和失败保留尺寸；展开截图不误勾选；长列表下滑不改变页面高度 |
| 数据同步 | 两端新增、修改、删除与并发返回，旧结果不覆盖最新记录 |
| Markdown | 完整导出导入、中文、嵌套字段、坏文件拒绝、旧JSON兼容 |
| 安卓录音 | 真机录音、拒绝权限后恢复、取消、后台切换、网络失败与草稿保留 |
| 安卓提醒 | 实际锁屏通知、完成后撤销、修改时间、重启恢复、强行停止后恢复 |
| 应用更新 | 从旧版实际升级，哈希、版本与签名正确，取消安装后旧版仍可使用 |
| 发布 | GitHub与正式部署对应同一提交；发布APK可下载，更新清单匹配文件 |

浏览器尺寸模拟、原生消息模拟和Java测试分别验证各自范围。它们不能代替实体手机的麦克风、系统权限窗口、锁屏通知和真实手势性能。本项目未宣称已完成这些真机验收。

## 7. 给别人复刻时应交付的内容

源码及依赖锁文件、本文、配置变量模板、数据库初始化说明、安卓构建与签名备份说明、发布流程、测试资料说明和图标来源链接应一起提供。分享自己的修改时说明仓库版本、哪些是网页功能、哪些需要新APK、哪些外部服务尚未配置。

`.env.local`、`.android-signing/`、私人导出、临时测试输出和本机路径无需交给复刻者。图标采用本地WebP，记录真实Thiings条目；再次公开分发素材前核对[Thiings使用条款](https://www.thiings.co/terms)，不要把来源说明当作授权结论。

建议向AI描述修改时，提供“进入路径＋当前表现＋期待结果＋保留的数据＋验收例子”。例如：

> 修改“观影评分→作品→第二季→观看进度”的评分输入。一季全部看完后，我要逐字输入5.5；输入5时不要收起或保存，点保存后才写入5.5。保留其他季的观看记录，并用刷新后数据仍在验证。

记录每次改动的原因与验收结果，保存失败过的方案及撤回理由。复刻者就能知道哪些选择来自实际问题，也能在下一次维护时避免重复踩坑。
